# archive/

[← к README](../README.md)

История митапов, чтобы прошлые старт и финал оставались на сайте и в репо.

| Файл | Что это |
|------|---------|
| [`meetups.json`](meetups.json) | `"номер": "sha коммита"` — откуда CI пересобирает прошлый митап |
| `<N>.md`, `<N>-close.md` | копии `open.md` / `close.md` митапа N, чтобы удобно читать и сравнивать |

Сайт собирается **из коммитов**, а не из этих `.md`: у старого митапа свои layout'ы, тема и
зависимости, и только его собственный коммит воспроизводит их точно. Копии `.md` нужны людям и
агенту — посмотреть, что было на слайдах, без `git show`.

## Как добавить митап в архив

Делаем перед тем, как править контент под следующий митап (пример: 32 → 33).

```bash
git rev-parse HEAD                 # sha последнего коммита 32-го митапа
cp open.md archive/32.md
cp close.md archive/32-close.md
```

```json
{
  "31": "179f6517db52f069b71963897982b80690ada28f",
  "32": "<sha из git rev-parse>"
}
```

Проверка: `pnpm build:archive 32` собирает `dist/32/{open,close}`. Подробнее о сборке — в
[scripts/README.md](../scripts/README.md#архив-прошлых-митапов).
